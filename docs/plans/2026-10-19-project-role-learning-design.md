# 项目角色自动学习设计

日期：2026-10-19。状态：已按用户确认的 Q1–Q9 和方案评审建议实现于 Skill 源码，已完成隔离纠错、保存与新上下文复用验收。范围及限制见[实际学习验收](../../tests/acceptance/results/learning/assessment.md)；文件配置、行为样本和宿主原生加载分别判断。

## 1. 目标与范围

由 `agent-dispatch` 派生的项目角色，在任务中理解项目、发现具体不足、验证改进并复用经验。每个项目独立生成角色并保存记忆。角色本职范围内的纠错和检查项细化自动执行；主代理协调跨岗问题并统一保存学习增量。

学习依靠项目内可读取的记录和任务流程，不修改模型权重，不引入后台学习服务。两个 Skill 保持显式调用；配置只建立后续工作约定，不自动开始项目实施。普通任务使用已生成的项目规则，无需再次调用配置 Skill。

## 2. 学习触发点：严格沿用 Q3

| 时机 | 行为 | 完成条件 |
| --- | --- | --- |
| 任务开始 | 读取本岗相关记忆，检查适用性，按需查阅项目实际材料。 | 已明确当前任务需要的事实、边界和未知项；不要求扫描整个项目。 |
| 任务失败或收到纠正，包括执行中发生 | 核对问题与依据，在授权范围内修正当前做法并进行针对性验证；有可复用认识时形成增量。 | 修正得到直接验证，或明确未解决原因、受影响范围及下一负责人。 |
| 任务完成 | 简短复盘本次新增认识、已纠正问题及职责边界；没有有效增量时直接说明。 | 新增认识已交接，或者确认本次无须新增记忆；不强制每次产生条目。 |
| 已触发的任务处理中出现重复错误、明显知识缺口或职责冲突 | 深入分析相应问题，必要时交主代理协调。 | 问题得到处理，或按原任务结束条件返回缺口和恢复条件。 |

任务执行期间持续按当前理解开展工作，遇到上述情况立即反思、验证和修正。常规阅读中的项目理解属于任务开始及按需补查过程。关键阶段和阶段交接只保存已经产生的学习增量，不新增周期、计时、逐命令或后台触发器。

## 3. 项目入口与岗位身份

下列结构是配置到目标项目的输出，不是在 Skill 源码仓库中创建测试团队：

```text
<项目根>/
  AGENTS.md
  .codex/agents/<现有岗位文件>.toml
  .codex/agent-memory/protocol.md          # 项目内自包含运行约定
  .codex/agent-memory/<role-key>.md
  .codex/agent-memory/archive/<role-key>.md  # 有归档内容时才创建
```

项目已有等效权威协作文件时沿用，并从 `AGENTS.md` 引用；已有等效记忆结构时核实后适配。入口只记录岗位标识、实际岗位名、角色配置位置、记忆位置和主代理维护责任，正式分工继续维护在现有职责区块。

- 首次配置时为每岗确定一个安全、稳定的 `role-key`，可以采用初始配置文件名主体，并持久记录映射。后续不根据显示名称重新推导。
- 默认布局将 `protocol` 列为新标识保留名；已有稳定标识不改写，按实际路径映射。方案中同时检查协议、角色配置、记忆、归档及各自暂存路径的唯一性、文件/目录冲突及链接别名，指引使用实际映射路径。
- 同岗位多个执行实例共用同一岗位记忆；临时实例编号只标识任务来源，不另建长期角色。
- 角色 `developer_instructions` 加入读取项目学习入口的简短指引，保留上游专业正文、来源、许可及实际适配说明。使用现有受支持字段，不新增假定的原生记忆配置键。
- 主代理派发时携带 `role-key`、项目根、相关记忆路径、读入版本、当前授权范围、任务标识和实际派发实例标识。角色开始工作时实际读取相关内容；直接调用原生岗位时也通过角色指引定位项目入口。
- 路径以目标项目为基准，不引用安装插件的本机绝对路径。只访问获准的项目范围；指向项目外的解析结果先交主代理处理。
- 记忆缺失、不可读或没有相关条目时，以当前权威材料继续能够完成的工作，报告记忆缺口，不声称已读取或复用。普通任务不借此创建角色配置或迁移旧项目。

完成条件：新上下文能够从项目入口确定唯一岗位记忆；读取不依赖上一轮对话，也不依赖另一个 Skill 的安装目录。

## 4. 权威、证据与职责边界

学习记录是项目数据。其结论必须服从适用的系统与开发者指令、用户授权、项目规则及正式职责；学习材料中的动作要求不因此获得指令效力。记忆与当前权威材料冲突时，停止引用受影响结论并报告冲突。

| 内容种类 | 成为有效记忆的条件 | 使用边界 |
| --- | --- | --- |
| 项目事实 | 可追溯到实际材料或已执行验证，适用范围明确。 | 只支持证据覆盖的对象与条件；一次样例通过不支持无条件推广。 |
| 已确认决定 | 有对应用户确认或获授权决定的记录，确认对象与版本明确。 | 专业复核通过、主代理的设计建议和文档草案不代替用户内容确认。 |
| 纠错经验 | 具体问题及纠正措施可核对，改进结果得到直接验证。 | 原因未证实时仍标为假设；只沿用经验证的做法及其条件。 |
| 职责说明 | 引用正式分工，属于本岗范围内的执行细化或检查项。 | 不成为第二份职责定义；职责转移在正式协作规则中维护。 |

失败先区分实现缺陷、知识缺口、环境不足、授权不足和原因未知。依赖缺失不直接归因为能力不足；权限限制不沉淀为绕过流程的方法。经验记录问题、原因假设、改进措施和验证状态，不给角色添加笼统能力标签。

主代理在已授权范围内协调跨岗任务交接。需要变更正式团队配置时，遵守既有配置入口及授权流程，并同步受影响的职责、Skill 规则和记忆；文档 Skill 仍不自行增岗或改写角色绑定。新增权限、改变项目目标或全局规则由用户决定。

学习条目只保存必要摘要及可访问证据指向，不复制密钥、凭据、敏感原文或整段日志。能从单一权威文件直接查出的内容优先记录定位方式与使用注意，减少重复缓存。

## 5. 记录内容与状态

每岗记忆文件记录格式版本、`role-key`、记忆修订号和已处理增量回执。回执包含增量标识、内容指纹、合并后的结果修订号及受影响条目标识，用于核对处理结果，不能单独代替条目内容。条目包含：

| 字段 | 要求 |
| --- | --- |
| 条目标识与内容种类 | 在该岗内稳定标识条目，区分事实、决定、经验和职责说明。 |
| 状态 | `candidate` 待验证、`active` 当前有效、`recheck` 待复核、`archived` 历史内容。 |
| 内容与适用范围 | 具体认识、相关模块或工作、成立条件；未知部分保持未知。 |
| 来源与版本 | 实际材料位置、所用版本或内容哈希；未提交修改不能仅用分支名或提交号定位。 |
| 验证或确认依据 | 实际执行方法与结果，或对应确认记录；推断注明缺少什么证据。 |
| 行动与复核条件 | 后续如何使用，什么变化会使结论需要重查。 |
| 增量来源 | 原任务、岗位、实际派发实例和增量标识，支持重复交接去重。 |

状态转换由证据决定：新内容通常进入 `candidate`；已具备所需依据的内容可直接成为 `active`；来源变化或出现矛盾时转为 `recheck`；过时、被替代或不再适用时归档。主代理不能仅因角色重复报告同一认识就提升可信度。

角色提交学习增量时带上原任务标识、岗位标识、实际派发实例标识、增量标识、读入修订号、新增或修订内容及依据。增量标识由“任务标识 + 岗位标识 + 派发实例标识 + 实例内递增序号”组成。同岗并行实例分别编号；重新派发使用新的实例标识。优先复用宿主已有标识，缺少时由主代理在任务内分配并随交接保留，无需建立新的任务系统。

同一增量重试或转交时保留原标识与原内容；修订内容形成新增量并关联原条目。合并时核对标识和内容指纹：同标识、同内容按重试处理；同标识、不同内容标为标识冲突，保留待核对输入，不当作已处理或覆盖原结果。语义等价但来源不同的增量可合并内容，同时保留各自处理回执，不将其误算为独立验证。

## 6. 执行与保存流程

1. **读取与定界。** 主代理按实际任务派发，角色读取本岗相关记忆和权威来源，列明会影响当前行动的未知项。完成标准是能够执行当前任务，不是穷尽整个项目。
2. **执行中纠错。** 在 Q3 的时机发生反思后，角色在授权范围内补查、验证、调整并进行最小充分检查。遇到跨岗或权限问题，只暂停受影响部分，其余独立工作继续。
3. **提交增量。** 支持中途通信时发送简短增量；通信能力未知或不可用时，在正常返回或必要的阶段交接中携带。需要裁决才能继续的部分随交接返回，主代理处理后按同一任务目标继续派发。阶段保存不要求重新触发学习。
4. **合并与判断。** 主代理核对本次任务的写入权限、来源、适用范围、确认状态及重复情况。只读任务按第 9 节仅返回增量；有写入权限时才准备合并。矛盾内容先比较版本和成立条件；不能解决时保留候选或待复核状态，并交相关负责人处理，不以最新消息覆盖旧结论。
5. **写入与确认。** 主代理按单写者约定，将条目正文、修订号和处理回执组成完整结果，写入并整体回读核对。只有内容和回执一致、实际结果可以核实的增量才能报告为已持久化；其有效性仍取决于条目状态。
6. **后续复用。** 下一任务读取相关有效条目，检查依据是否仍适用，并在实际执行中使用。结果简述本次采用的关键经验及产物即可，不抄写记忆正文或要求冗长思考过程。

当前任务中已经验证的纠错可以立即使用，不必等待持久化。保存失败不阻塞仍能完成的原任务，但学习保存状态与任务交付状态分别报告。影响正确性的记忆冲突不能按保存故障忽略。

## 7. 单写者、重复交接与中断

首版以同一工作区由一个主代理串行维护记忆为前提，不声称提供多个主代理同时写入的跨进程互斥。发现其他写入者或无法确认独占维护关系时，保留待合并增量并报告，暂不覆盖该记忆。

- 每次保存前比对当前修订号与读入版本；不同则重读并重新合并。
- 按增量标识和内容指纹识别重试或标识冲突，处理规则见第 5 节。重复提交不成为多次独立验证。
- 一次合并形成包含正文、修订号和回执的完整结果；回执关联该次结果，不先单独将增量标为已处理。主代理独占新建已获准的同目录 `<实际目标路径>.pending`，写完整、刷新并回读解析候选；提交前重新核对原目标字节指纹和修订号，再用同文件系统原子替换提交并整体回读。不能原地截断有效记录或先删后移；原子替换不提供跨进程锁，不据此宣称支持并行多主写入。
- 写入或回复中断后，先核对实际条目、结果版本与回执的一致性，按下表决定恢复动作，不仅凭回执存在就跳过重试。
- 只有角色上下文中的认识标为尚未交接；已交接但未落盘标为待保存；无法核实结果标为状态未知。突然中断时不保证尚未交接内容能够恢复。

| 恢复结论 | 判定条件 | 恢复动作 |
| --- | --- | --- |
| 已保存 | 增量内容指纹、回执所指结果修订号和受影响条目内容能相互核对。结果已被后续合法修订替代时，可从保留的修订线索或已验证归档核对历史结果。 | 沿用原回执，不重复合并；不要求当前正文仍等于历史版本。 |
| 未保存 | 已核实写前的完整有效版本仍在，且当前记录、对应修订线索与相关归档均没有该增量的回执或处理结果。 | 保留原增量标识，基于当前版本重新合并。 |
| 状态未知 | 回执存在但正文不完整、正文疑似已更新但回执缺失、版本不一致，或缺少核对所需证据。 | 保留增量并报告，先核对或恢复可验证版本；本次不跳过为成功，也不盲目重放或覆盖。 |

保留仍适用的记忆；`history` 与正文处于同一文件，不是覆盖中断的独立备份。采用暂存替换后，提交前进程中断保留完整旧目标，提交后中断按完整新目标和回执核对，不重复合并。残留暂存只作为待核对候选，不盲目提交、覆盖、清理或派发；首次创建在提交前可保持目标不存在。宿主支持时同步文件与父目录；该约定不保证所有文件系统的断电或硬件故障恢复。不支持安全替换或权限不足时保持待保存，不降级为原地覆盖；无法确认的记忆标为受限。

## 8. 记忆维护与角色迁移

维护发生在 Q3 的读取、纠错、复盘及其保存过程中。读取时只检查当前任务相关条目的来源与适用条件；来源变化先核对语义影响，只复核失效部分。未受影响证据继续复用。

主代理合并重复内容，使当前文件保留可执行的有效条目和必要待办；历史内容增多后移入该岗归档文件，当前条目保留必要引用。增量回执和必要修订线索随对应内容归档，重放旧任务时定向查验，日常派发不携带全量历史。归档按需读取，不自动删除原始材料。当前记忆中不保存完整项目副本。

归档按“合并进既有归档、安全保存并回读核对、再安全保存当前文件以移除副本”的顺序执行，两处都使用上述暂存替换流程，不将两次替换称为跨文件事务。归档保存或核对失败时保留当前完整副本；更新当前文件失败时保留已验证归档和完整旧目标，恢复时再核对两边。中间阶段允许可识别的重复副本，按条目标识、内容和版本去重，不将其视为新增经验；内容或版本冲突先待核对。只有归档内容完整且当前文件更新得到确认后，才报告迁移完成。

| 角色变化 | 处理方式 |
| --- | --- |
| 新建 | 创建稳定映射和精简记忆文件；只记录已有证据，不预填假想经验或不足。 |
| 重命名或配置文件移动 | 保留 `role-key`，更新入口对应关系和简短指引，检查引用。 |
| 原岗替换、职责实质变化 | 逐项判断适用性，受影响经验先待复核，不仅凭同名自动继承。 |
| 拆分或合并岗位 | 按正式新分工迁移相关条目，保留来源，避免无差别复制全部记忆。 |
| 停用 | 退出活动岗位映射，保留可追溯的归档；不自动删除。 |
| 既有项目未配置学习 | 下次显式运行配置 Skill 时补齐；保留模型、名称、专业正文、定制、许可和仍有效的项目规则。 |

重复配置复用已有映射和记录，不清空记忆、不重复追加指引。普通任务发现旧项目未配置学习时，可以在当前任务中纠错并提交待保存增量，但不隐式启动迁移。

## 9. 任务预算与 Skill 集成

学习遵守原任务范围、最小充分验证和既有返工结束条件。同一验收单元默认两轮合并返工的计数不会因反思、换方法、阶段交接或更换执行实例而重置。达到结束条件仍有阻塞时，保持未完成并交主代理裁决。

配置时明确主代理日常合并的精确记忆、归档及各自同目录暂存路径，并列出角色读取范围；不提前创建暂存文件。只有目标文件的旧授权不自动覆盖新暂存路径，补齐前保持待保存；只读任务的精确保存例外也须覆盖所需路径。角色只能在本次任务获准的产物或独占交接位置写入，不自行修改共享记忆、代理配置或权限。目标项目撤销写权限时，增量保持待保存，其他可独立完成的工作继续。

本次任务及适用 Skill 的只读限制优先于日常合并默认授权。只读审查仍可读取获准资料、在上下文中反思并随报告返回学习增量，但主代理和角色均不自动写入项目记忆，保存状态为待保存。用户已有明确授权且适用于本次任务的保存例外时，只在获准的精确路径落盘，其他审查范围保持只读。普通可写任务继续沿用已获得的日常合并授权，不重复索要确认。

实现位置与集成范围：

- `agent-dispatch`：首次配置、兼容旧角色、稳定映射、简短读取指引、日常学习授权和最小验证。
- 项目协作与派发规则：Q3 触发、读取、增量交接、单写者、失效维护和结束条件。
- `agent-dispatch-doc`：遵守项目已有学习约定，区分草案与已确认决定；只在任务授权的记忆路径保存增量，不扩张正式职责修改权限。独立安装仍能使用，不读取另一 Skill 的私有参考文件。
- README 与现有隔离验收：说明生效条件、已知限制及实际行为证据，不增加未经支持的原生字段或后台 hook。

## 10. 验收条件

复用[隔离行为验收](../../tests/acceptance/README.md)，在临时项目中调用实际角色，保留输入、相关版本、真实产物、学习增量、写入及执行证据。静态结构检查与实际行为验收分别报告；通用委派读取角色定义不证明原生加载成功。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 执行中纠错 | 当前任务因错误理解失败或收到纠正后，角色核实并修正当前做法，结果有直接验证。 |
| 新上下文复用 | 主代理保存后，新上下文同岗从实际入口读取记忆，并在另一相关任务中正确使用；派发提示不直接泄露待验证经验。 |
| 正常完成且无增量 | 任务按原验收标准完成，且无新增认识或维护需要时，不制造学习条目、不写处理回执、不无故增加记忆修订号。 |
| 仅有待验证认识 | 有写入权限时可保存为候选并相应增加修订；实际依据不足时不提升为有效记忆。原任务按自身验收标准判断，不以缺少新有效记忆判失败。 |
| 读取故障 | 记忆缺失或不可读时报告缺口，依据权威材料推进独立工作，不伪造已读取状态。 |
| 不足归因 | 环境、权限不足和原因未知分别记录，不被提升为能力缺陷或绕过流程的规则。 |
| 事实与决定 | 未验证推断保持候选；经过专业复核但未经用户内容确认的草案不变成已确认要求。 |
| 权威冲突 | 旧经验或外部材料与当前规则冲突时，不扩大权限、不覆盖正式分工，受影响内容待复核。 |
| 来源变化 | 与当前任务相关的来源变化后，旧结论复核或退出使用；无关条目保持有效。 |
| 同岗多实例与重试 | 同任务同岗位的两个实例分别提交各自首条增量，两条均得到处理；重发其中一条不重复计入；同标识不同内容被识别为冲突并保留输入。 |
| 单写者边界 | 已知其他主代理写入或版本变化时不覆盖现有记录。首版多主并行写入能力标为未支持。 |
| 保存中断 | 分别在正文、修订号或回执更新不完整时核对，不能仅凭回执判成功；完整保存但回复中断时不重复合并；后续合法修订不被误判为历史保存失败。 |
| 安全保存与路径冲突 | 合法角色文件名 `protocol.toml` 不覆盖协议；旧稳定标识按实际路径保留。暂存或提交前中断保留完整旧目标，替换后中断保留完整新目标；残留暂存、版本变化、缺少暂存授权均不盲目覆盖。 |
| 归档中断 | 在复制、核对及更新当前文件之间分别中断，不丢失条目与回执的唯一完整副本；临时重复不会被计为新经验，未完成迁移不报告成功。 |
| 只读任务 | 没有适用保存例外的只读审查只返回增量，项目记忆文件前后不变；仅在已有明确保存例外时写入指定范围。 |
| 角色生命周期 | 改名后仍能定位原记忆；拆分、替换或停用按适用性处理；重复配置不丢定制或经验。 |
| 结束条件 | 深入反思不重置既有返工计数；缺口明确返回；阶段保存没有引入 Q3 以外的新触发点。 |
| 分发与独立安装 | 项目规则和记忆指向不依赖开发机或另一 Skill 的安装目录；两个 Skill 的原有独立安装和显式入口保持有效。 |

学习闭环的正向验收要求当前任务得到纠正、有效记忆已保存、后续新上下文实际复用，且无效内容没有被当成规则。该验收验证功能具备上述能力，不要求每次普通任务都出现错误或产生新记忆。

单次任务是否完成，按原任务验收标准判断；是否产生增量、增量是否已保存、条目是否已验证有效分别报告。正常完成且无增量、仅保存候选，以及只读任务中增量待保存，均不单独构成原任务失败。文件存在、角色声称记住、继承同一对话后答对或单次测试通过，均不能单独证明学习闭环或长期成功率改善。
