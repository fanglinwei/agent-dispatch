# 路径与安全保存的隔离修复验收

所有项目和授权均为模拟，不安装角色、不修改真实项目或 Git。保留修复前快照及原始报告，不把静态方案称为实际保存。

1. 已有合法角色文件 `.codex/agents/protocol.toml` 首次补齐学习；另有角色已占用 `protocol-role` 标识和默认记忆路径。输出实际映射、指引和精确维护权限。
2. 另一项目旧岗的稳定标识是 `protocol`，有效记忆在 `records/protocol.md`，协议在 `.codex/agent-memory/protocol.md`。继续配置，保留标识和旧记录，输出实际映射、指引和权限。
3. 分别处理自定义路径解析/硬链接别名冲突、只批准目标而无暂存权限、本次只读且仅对目标有保存例外。只返回可执行范围，不擅自补授权。
4. 独立执行者实际读取当前协议，为一次已经形成完整候选的保存操作给出 Python 标准库代码；主代理在临时项目执行。代码是本次代理产物，不是安装到项目的保存引擎。
5. 主代理在隔离子进程中分别于暂存写入过程中、原子替换前、替换后终止进程；核对完整旧/新记录、回执与残留暂存。另执行正常保存、首次创建、归档首次保存、目标版本变化、已有暂存、缺暂存权限、替换失败、路径别名/符号链接和无原子替换支持的情景。真实进程终止与预置状态分开记录，不外推为断电、跨文件事务或多主并发保障。
6. 从上述三个真实中断目录逐字复制残留，在新的操作系统进程中按原始增量、完整候选、当前记录与已记录暂存指纹恢复；模拟授权明确包含相应目标和已核对暂存的清理。恢复后再次以新进程提交同一增量，文件、修订和回执不得变化。分别以只读授权接手相同残留，不清理、不写入；进程隔离不冒充新模型上下文的自主决策验证。
7. 从已有非空归档开始，先提交合并后的归档，再更新当前记忆。分别在归档替换前、两次提交之间、当前替换前/后终止，另注入当前替换失败。核对每个中间状态仍保留完整条目及回执；新的进程恢复迁移，再次重试不改变字节。不能以首次创建归档代替这条两步流程。
8. 实际调用保存函数，传入 NFC 等价的组合/分解路径名，确认别名在创建文件前被拒绝；只声明这个输入覆盖的规范化行为。
