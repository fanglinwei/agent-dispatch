# 隔离行为验收

`fixtures/` 是可重放的项目输入，`results/` 保存最近一次真实重放的产物与证据。它们不是安装器、预置项目团队或用户项目的实施依据。测试中的用户回复是明确标注的模拟输入，不代表实际用户已经接受这些文档。

`npm test` 离线核对这些实际产物及当前 Skill/输入的 SHA-256，不启动模型、访问网络或修改用户配置。它会拦截陈旧证据、丢失供稿或复核、改坏的岗位正文、被覆盖的定制，以及越过内容确认的入口变更。它不能自行判断文档专业质量；该项由真实岗位贡献、专业复核和主代理验收负责，不靠回复关键词证明。

## 每次重放

1. 在系统临时目录创建全新工作区，将 `fixtures/team` 和 `fixtures/documents` 分别复制进去。不要在本项目、游戏项目或用户级配置中配置测试岗位，不覆写 `HOME` 或 `CODEX_HOME`。只有主代理写测试角色配置，子代理只能在独占的供稿/复核路径产出文本。
2. 读取当前 `agent-dispatch` 及参考文件，执行 `team/initial.md`。先保留完整方案，再提供明确标为模拟用户的方案确认，然后实际生成角色 TOML、协作规则和同提交许可。保存为 `results/team/initial/`。固定上游原件和许可在 `fixtures/team/upstream`，来源和原件哈希在 `source.json`，可联网核实固定提交，但不运行上游安装脚本。
3. 在生成的 Content Creator 中加入 `model = "gpt-6.1-sol"`、`model_reasoning_effort = "high"`，以及“用户定制：本项目审稿”的职责补充，保存完整 `before-addition/` 快照。执行 `team/addition.md`，核对旧团队后展示并确认增岗方案，实际应用并保存 `after-addition/`。用可用 TOML 解析器解析输出，再逐字比较原岗正文、原配置与许可。没有解析器时记录 PARTIAL，不能把快照字符串检查当成原生 TOML 解析。
4. 在同一配置上向新的独立代理显式使用 Skill，重放 `team/repeat.md`。可提出真实缺口，不提前告知预期选岗结论；代理不得写配置。主代理记录请求前后全树哈希及代理结论到 `results/repeat.json`。没有改动才是幂等通过，单独调用文件生成脚本两次不算。
5. 读取当前 `agent-dispatch-doc` 与参考文件，执行 `documents/request.md`。展示并保存完整文件方案，再输入模拟方案确认。主代理为共享文档唯一写入者，按 fixture 中五个实际岗位定义逐个委派专业供稿；每岗独占 `contributions/<role>.md`，不可递归委派。UI 设计实际读取并使用 fixture 的 `visual-layout`；审查岗位只编写检查方法，不因 `defect-evidence` 缺失阻断全部文档。
6. 整合真实供稿成 `docs/implementation.md`，另写 `docs/README.md` 草案索引。每岗读取整合版，只读复核其专业范围，并输出独占的 `reviews/<role>.md`。修正实际冲突后让受影响岗位复核。验证 R1～R6 流程、容量满、失败保留输入、接口/状态/未知项、每岗具体工作和可执行验收方法；旧 React、清空输入及 PASS 不能被继承。没有实际项目执行记录时仍为 NOT_RUN。
7. 专业复核完成但尚无内容确认时，保存 `results/documents/`，必须为 DRAFT，原岗位、技能绑定、旧文件及 `AGENTS.md` 不变。随后在另一个隔离副本中给出明确标注的**模拟内容确认**，才将新文档升级为实施依据并更新已约定的入口；保留旧文件为历史，保存 `results/promoted/`。这只验证批准后的状态迁移，不批准真实用户项目文档。
8. 保存真实调用身份、方案/模拟决定、贡献与复核路径/哈希、TOML 解析器和检查结论、未覆盖项到 `results/replay.json`；记录重放所用版本、完整 `skills/` 与 `fixtures/` 文件哈希。路径均相对本测试目录，不能留下临时目录依赖。运行 `npm test`，再独立审阅行为证据和实际文档，不能为了使测试通过把未参与或未执行项改为 PASS。

## 判定标准

| 场景 | 必须从实际文件核对的结果 |
| --- | --- |
| 首次配置 | 非软件项目目标和完成标准明确；采用必要上游岗位；原名/描述/完整正文、固定来源与完整许可可追溯；没有内容制作或实施文档越界。 |
| 真正增岗 | 先核对已存在的实际职责；新增专业责任有缺口依据；原模型、定制与内容全部保留；交接清楚，许可复用。 |
| 重复调用 | 新独立代理基于实际项目判断复用；前后所有配置字节一致，没有重复岗位、规则或许可。 |
| 团队文档 | 五岗都有可定位的专业工作、输入输出、依赖和完成条件；都有实际供稿与整合版复核；技术/交互/验收一致，引用可用，不依赖旧设计。 |
| 确认门槛 | 方案确认不等于内容确认；专业复核后仍是草案，未经内容确认不改实施入口；模拟内容确认后才能升级，实际开发仍未运行。 |

本组用例刻意不覆盖所有项目类型、宿主版本、网络故障和真实法律/发布工作；没有证据的能力不得从这些测试外推。
