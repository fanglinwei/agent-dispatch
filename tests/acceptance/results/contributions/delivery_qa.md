## 3. 可执行用例

沿用 R1～R6，不另建平行需求编号。同一 R 下按场景名关联证据。以下表格每一行均须独立记录实际结果；当前结果全部为**未执行**。

| 需求/场景 | 前置与输入 | 操作 | 预期与通过依据 | 最小证据 |
| --- | --- | --- | --- | --- |
| R1 正常列表与身份 | 列表至少含不同身份的 A、B；标题/展示字段取真实契约。 | 首次进入列表，观察加载后选中 B 的详情链接。 | 加载与列表可区分；有真实活动和可理解入口；进入 B，未误用列表序号、A 或假数据。 | 列表响应与 A/B 身份、列表及 B 详情画面/状态、点击路径。 |
| R1 空列表 | 列表接口返回契约规定的零活动响应。 | 进入列表，等待请求结束。 | 显示空态而非加载/报错；无虚构活动或指向空详情的报名入口。 | 空响应、结束后的空态。 |
| R1 读取失败恢复 | 首次列表读取受控失败，第二次返回 A/B。 | 进入列表；出现失败后恢复网络/响应，主动重试一次。 | 错误和重试可理解；重试中不重复请求；成功后显示实际列表，无成功报名画面。 | 两次读取的顺序/次数、失败与恢复画面。 |
| R2 详情、返回与不可用 | 可用 B、已确认不存在/不可访问的标识、详情失败后恢复样例。 | 从列表进入 B，核对内容后返回；再分别打开不可用详情及读取失败详情并重试。 | 活动身份贯穿详情和表单；返回可达；不可用/加载失败不给空壳提交表单；可用数据恢复后才开放报名。 | 标识及响应、各分支画面、返回与重试操作。 |
| R1/R2 旧响应隔离 | A 详情延迟，B 快速返回；若实现支持页面切换，使用其实际操作。 | 进入 A 后立即切到 B；再释放 A 的延迟响应。 | B 的标题、容量、草稿与结果不被 A 覆盖，不向错误活动提交；不支持该切换则记录不适用依据。 | 请求顺序/活动标识、释放前后 UI 与当前活动上下文。 |
| R3 必填/格式/长度 | 每个已确认字段的合法值、空值、各格式非法值，以及长度边界 `n-1/n/n+1`（仅对存在该约束的字段）。 | 保留其他字段有效，逐一输入非法/越界值并提交；从错误摘要定位字段；纠正为边界合法值后提交。 | 非法时无报名请求，所有原值保留；字段标签、错误和修正办法对应；合法值通过校验，进入一次提交；不擅加未确认限制或静默截断。 | 最终规则表、合成输入、校验前后值对照、错误关联/焦点、报名请求计数。 |
| R3 服务端字段拒绝 | 客户端合法输入，服务端返回契约中的字段错误及一个未知字段错误样例；拒绝保证无写入须由契约证明。 | 提交并接收字段拒绝；修改相关字段，再按允许的恢复条件提交。 | 已知字段就地关联；未知字段进入表单级反馈；其他值不丢失；无成功画面；退出忙碌，恢复动作与拒绝语义一致。 | 业务响应/无写入依据、错误定位、值对照与后续请求。 |
| R4 读取时满额 | 已确认语义下 `capacity=2, confirmedCount=2`；另取计数超容量的可控样例。 | 进入详情；尝试键盘/触控触发提交入口（若展示）。 | 有持久满额说明和返回操作；不发送报名；不显示负余量，不把超额当可报名。计数异常按确认后的前端方案处理。 | 容量响应、提示/禁用及操作证据、报名请求数为零。 |
| R4 提交竞争与刷新失败 | 初始可报名；填满合成字段；提交返回 `CAPACITY_FULL`；后续详情刷新失败。 | 提交，收到满额；触发允许的刷新；核对原值并再次尝试提交。 | 转满额并退出提交中；所有值保留，无成功、不循环网络重试；刷新失败不抹去满额结论或重开报名；仍可返回列表。 | 提交及刷新响应、值对照、状态与后续报名请求计数。 |
| R4 最后一个名额 | 真实隔离服务端确认 `capacity=1, confirmedCount=0`；两份不同有效报名；先核实服务端容量承诺。 | 两个客户端在同一时段提交不同报名，随后读取实际记录/计数。 | 若确认一人一名额规则，至多一份成功，另一份明确满额；最终计数/记录不超额，两个 UI 各符合实际结果。客户端模拟不能证明此项。 | 两次请求时序/标识与响应、同活动的实际新增记录和最终计数。 |
| R4 容量异常/未知 | 缺失、负数、非整数、`0` 等按真实契约逐项确定可达性与合法语义。 | 读取各样例并尝试报名。 | 不编造无限/可报名状态；按确认的异常处理开放或阻止操作；不展示 `undefined`/负余量。不接受“0 必然满额”为未经确认断言。 | 契约条目、样例响应及 UI；不可达样例记录不适用原因。 |
| R5 明确成功与返回 | 合法字段、充足容量；提供满足最终成功契约的权威响应。 | 提交一次，核对结果；浏览器后退，再返回结果/详情。 | 仅在响应满足约定成功依据后显示成功，关联正确活动；仅显示实际存在的结果字段；没有自动重发或再次提交同一报名的主入口。 | 成功响应与活动/请求关联、结果页、后退前后请求数及服务端新增效果。 |
| R5 业务重复报名拒绝 | 已确认服务端“相同报名人”定义、重复响应及无新增/返回既有结果语义；已有一份报名。 | 使用满足重复定义的合成输入再次发起获准测试提交。 | 按契约说明重复或恢复既有结果；不伪造一次新成功；不新增第二份记录或重复占名额（若这正是确认的业务规则）；保留字段和合适下一步。 | 重复规则、初始/最终记录与计数、业务响应和 UI。规则未知时受阻，不能仅凭错误码断言无重复。 |
| R5 权限错误 | 实际公开接口权限策略已知；获准测试环境能提供对应 401/403 或业务拒绝，不获取/扩大他人权限。 | 分别在详情读取及报名提交注入/触发真实存在的权限拒绝。 | 不显示成功或泄露受限详情/报名记录；提交字段保留；结束忙碌，提供可理解返回/恢复动作；不无限重试、不擅加登录流程、不显示原始凭据/调试堆栈。 | 权限策略、脱敏请求/响应、可见反馈/字段对照；服务端无写入仅以契约/记录确认。 |
| R5 不完整成功包与其他错误 | 2xx 但成功依据缺失/包不合法；另有实际 5xx、限流等样例及语义。 | 提交并接收各响应。 | 缺成功依据不得成功；5xx/中断不能自动认定服务端没写入；字段和原请求上下文保留；限流恢复遵循实际契约，无无限自动重试。 | 样例与映射依据、状态、请求数量；不确定结果所需后续证据。 |
| R5/R6 客户端重复触发 | 合法输入，提交响应受控延迟；能观察请求开始时间。 | 连续点击、双击、表单内多次 Enter，混合触控/按钮触发；请求未结束前重复触发重试入口。 | 同一进行中逻辑操作只发一份请求；提交前无异步空隙允许第二次调用；忙碌明确、焦点可用；收到结果后按实际终态处理。此项只证明客户端门禁。 | 输入事件序列、网络请求数量/标识、进行中与终态 UI。 |
| R6 网络失败保留输入 | 所有字段填合成值；具备可控断网；有明确“请求未发送”证据的失败方式及恢复网络步骤。 | 提交触发失败，核对每个字段和活动；恢复网络，主动点击重试；再分别使重试失败和成功。 | 失败与再次失败均不清空/改写字段，不自动离开；无自动连续提交；明确安全的重试沿用该活动及确认的快照，最终成功按 R5 断言。断网提示本身不等于“请求未发送”证据。 | 失败注入位置、未发送依据、字段前后对照、重试操作与请求/响应、最终 UI。 |
| R6 服务端已写入但响应丢失 | 真实测试服务端具备确认的幂等重放或结果查询；能在写入后丢弃响应并查询/读取记录。 | 有效提交后只丢响应；等待进入结果未知；执行规定的核对/安全重试，再查记录与计数。 | 先显示结果未确认并保留字段、原标识及快照；不生成新标识盲重提；核对恢复原成功，或同键重放得到同一逻辑结果；只有一份报名和一次容量占用。 | 写入时点/丢响应方式、原/重试标识与内容、查询/重放响应、初始/最终记录数及计数。 |
| R6 原结果仍未知 | 查询返回处理中/未知，或接口无可证明终态能力；先确认支持哪些分支。 | 提交超时后核对；连续操作恢复入口，尝试编辑、切活动后返回（若最终方案允许）。 | 不把“未找到”、本地取消或超时当作未受理；不以新标识绕过未决操作；保留原快照与未决上下文，文案不称已失败且未报名。没有安全重试能力时明确阻塞该流程，而非宣称 R6 全部通过。 | 查询语义、前后状态、实际请求内容/标识与次数、未覆盖原因。 |
| R6 服务端同键重放/并发 | 在幂等有效期与作用域内，使用同一标识及相同有效快照；另备同标识不同快照；实际服务端允许本次验证。 | 先顺序重放，再并发同键同内容；最后以同键不同内容请求。 | 依确认契约：相同逻辑操作只产生一份结果/占位；不同内容明确拒绝且不改写原记录；请求过期后的行为另按契约验证，未确认有效期不能宣称长期安全。 | 幂等契约、请求标识/内容摘要与顺序、响应、实际记录/计数。仅模拟或按钮计数不足。 |

## 4. 键盘、窄屏与反馈的执行方法

## 5. 执行判定与证据门槛

- **未执行**：只有方法、没有本阶段实际操作；当前全部应用用例在此状态。**受阻**：明确缺少构建、环境、权限、测试数据或契约，列出受影响场景与责任人。**不适用**：最终确认范围/契约能证明场景不成立，写明依据，不用来隐藏必需目标缺口。
- **PASS**：该构建/该环境的前置、操作、全部预期和所需证据完整对应，且执行完整结束。**FAIL**：实际结果违背已确认预期，附最短复现、输入/响应、实际与期望、构建环境及影响 R；缺陷交主代理分配，不自行改实现。
- **PARTIAL**：仅覆盖部分环境/步骤/证据；执行异常终止、退出状态未知、只有旧报告或片段不能标完整成功。浏览器模拟与适配层模拟可以证明自身范围，不外推真实 API、容量并发、权限和服务端去重。
- 成功/无重复/未占名额等涉及数据效果的断言需服务端权威证据；UI 成功截图、HTTP 状态或请求次数不能单独证明。失败保留输入需逐字段前后对照，不能只截一个仍有文字的字段。
- 最小完成门槛建议为：确认后的 R1～R6 正常、边界、容量竞争、业务/权限拒绝、失败恢复及键盘/手机用例有本构建证据；必需幂等/结果未知风险关闭；失败与未覆盖项逐项处理。支持矩阵与影响交付的剩余限制由主代理裁决并取得所需用户决定，本岗不代替最终完成声明。
- 复用相同构建、相同环境、相同范围的有效证据；实现变化、失败修复或新增覆盖缺口只补受影响用例。无新风险不扩为全仓测试或无关检查。

执行记录采用一个场景一条记录：`关联 R/场景 → 构建/环境/真实或模拟 → 前置与合成输入 → 操作/故障注入 → 期望 → 实际 → 证据位置 → 状态/未覆盖 → 交接对象`。证据路径与实际命令在执行后填写；当前不伪造包管理器、测试命令、HAR、截图、构建号或通过日期。

## 6. 本岗交接、依赖顺序与完成条件

1. 产品先交接流程、字段约束、重复报名规则和输入保留范围；前端核实实际接口、容量、成功依据、权限及幂等/查询；UI 给出对应状态与焦点。QA 可以先供稿，但契约未知部分不冻结断言。
2. 主代理整合并裁决第 7 节差异，形成新 DRAFT；QA 复核 R1～R6 映射、用例可执行性、失败注入、证据门槛和未知项，意见只交主代理，不改共享稿。
3. 专业复核和用户内容确认后，后续开发任务由前端实现并直接自测，交付可追溯构建、环境、契约及实际检查命令/退出状态；QA 在新的明确授权范围内独立执行受影响用例，UI 复核设计符合性，代码审查由 code_auditor 按其必需 Skill 独立处理。
4. QA 输出本构建的实际记录、失败复现、R 覆盖和未覆盖条件给主代理；前端接收可复现缺陷，产品/UI 接收预期或呈现争议，权限/服务端能力缺口由主代理协调既有负责人，不由 QA 扩权修改系统或增岗。
5. 修复后只补相关证据并复核其归因；主代理核对各岗结果、剩余阻塞和 6 项目标，负责交付决定。
