# delivery_qa 供稿

状态：DRAFT；仅方法设计，开发另起任务。依据最新目标、事实、产品流程、UI 状态和前端提案；旧设计不作依据。接口路径、字段与错误载荷统一引用前端权威提案，缺失不得补造。

| 需求 | 操作、预期与边界 |
| --- | --- |
| R1 活动列表 | 有数据、空列表、加载和失败分别呈现；可选活动进入对应详情。 |
| R2 活动详情 | 信息与所选活动一致；手机触控、键盘均可进入报名，容量状态可辨识。 |
| R3 表单校验 | 按已确认字段规则覆盖空值、边界和非法输入；错误关联字段，修正可继续，校验失败不发送报名。 |
| R4 名额满 | 覆盖剩余名额及 confirmedCount 等于或超过 capacity；服务端 CAPACITY_FULL 即使与旧页面信息冲突也提示已满，不呈现成功，并保留输入。 |
| R5 报名结果 | 仅明确成功响应进入成功结果；提交中禁重复触发。业务拒绝、权限错误与成功分开，错误后保留可恢复输入。 |
| R6 失败恢复 | 断网、超时和连接中断保留输入；可信核实未受理且不会迟后生效，或已证实的幂等保障覆盖同一请求，才允许用户主动重试；结果未知禁止自动重发，核实成功直接展示结果。 |

重复点击、键盘连续提交及请求未返回时的操作均检查请求次数；页面防重不证明服务端幂等；两种保障都未证实，相关执行检查才待条件。权限拒绝须可识别、无成功反馈且不暴露内部信息；状态码依契约，不新增登录流程。

未来需固定构建版本、浏览器与视口、隔离环境、权限模拟、可复位容量数据、错误注入及请求观测能力。每例记录需求号、前置数据、操作、预期/实际、时间、版本、脱敏截图及请求响应/日志关联证据，提供复现与清理步骤，不记录真实个人信息。

QA 先消费产品规则、UI 状态和前端契约，再向工程交用例与证据模板；工程回交构建、契约和复现材料，QA 验证后将同版证据交 code_auditor。本次文档检查为 standard；未来端到端 standard、权限分支 high 并独立验证复核。

本供稿自查为非独立，整合稿待实际复核，结论 NEEDS_EVIDENCE；构建、浏览器、API、代码审查及应用验收均 NOT_RUN，文档通过不等于应用通过。阻塞附位置、影响与证据合并退原负责人，最多两轮；仍阻塞交主代理裁决，受影响项保持未完成，修订仅复核变化与相邻影响。
