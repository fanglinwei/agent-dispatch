# ui_owner 供稿（DRAFT）

依据：已读项目规则、最新目标、当前事实、岗位定义、请求及获批文件方案。实际读取并应用 skills/visual-layout/SKILL.md；仅文档视觉设计。受众为社区活动报名工具用户，采用简洁、清晰、高对比的信息层级。旧稿的无限容量、失败清空及全通过无证据，不沿用。

页面与组件建议：活动列表用卡片显示名称、时间、地点与名额状态；详情页依次展示活动信息、容量提示和报名入口；报名表包含永久可见的标签、必填说明、字段错误与提交按钮；结果区区分成功、明确失败和结果待确认。具体输入、响应字段及错误结构由 frontend_owner 的统一契约定义，本稿不另定义字段。先确认显示所需信息，再交前端实现，成功结论仅使用服务端确认结果。

手机采用单列、可换行标题及全宽主要操作；320 CSS 像素宽度下无横向滚动，触控目标至少 44×44 CSS 像素。键盘按页面阅读顺序 Tab，原生按钮支持 Enter／空格，所有控件有清晰焦点环且不被底部操作遮挡；错误和容量状态同时使用文字与图标。正文对比度至少 4.5:1。

完整状态：列表空态说明“暂无活动”并提供重新获取入口；首次加载使用占位和文字，刷新保留已显示信息；请求中显示进度文字、设置忙碌状态并禁用重复提交。禁用旁说明原因。校验失败保留输入，错误与字段关联，提交后聚焦首个错误；状态更新通过可访问消息区播报，避免无故抢焦点。

容量满时，列表和详情显示“名额已满”，禁用报名入口；提交时收到 CAPACITY_FULL，同样保留表单并展示明确提示，提供返回活动列表入口。容量提示以服务端为准。网络失败保留当前会话输入；列表和详情可重新获取，表单只有前端确认未受理或具有安全重试保障后才开放重试。结果未知显示“报名结果待确认，请勿重复提交”，等待统一契约规定的核对或安全恢复路径，禁止提示再次提交。

UI 提供页面标注、组件状态表、色值／字号／间距和图标规格给前端；优先系统字体，装饰图标不重复朗读。前端确认状态映射及文本，QA 据此验收窄屏、键盘、焦点、名额满、错误保留和未知结果分支。后续逐项记录操作、预期、实际、截图或可访问性证据；本次只自查文档覆盖与契约边界。应用运行、浏览器、构建和功能验收均 NOT_RUN；整合稿专业复核及用户内容确认待完成，稿件保持 DRAFT。
