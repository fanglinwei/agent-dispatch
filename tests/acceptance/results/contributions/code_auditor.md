# code_auditor 供稿

状态：DRAFT；应用检查一律 NOT_RUN。已核实应用为 Vue 3 / TypeScript，接口由前端适配层处理；capacity、confirmedCount 和 CAPACITY_FULL 已存在，但 UI 尚未呈现容量满错误。旧稿的 React、无限容量、失败清空及全部通过结论不沿用。

实施顺序：产品、UI、前端先交付确认需求、接口契约及实际代码；QA提供同版本用例与可用证据；code_auditor只读审查差异及必要调用者，将问题交原实现负责人，跨岗分歧交主代理。范围包括列表、详情、校验、容量满、结果及重试保留输入。

从入口沿调用者追到适配层和结果消费端，核对参数、响应及错误分支一致；API具体字段只引用整合稿前端契约，不另造错误结构。逐项检查状态迁移及异步响应次序，防止旧响应覆盖当前活动；校验失败、网络失败及重试后输入仍在。比对容量展示与现有模型，检查服务端容量满错误能进入对应UI，客户端余量不能证明名额锁定。检查连点、回车及并发重试是否造成多次提交，响应未知时是否误报成功或盲目重发。检查越权入口、敏感数据与错误暴露；无登录需求不代表权限已验证。断网、超时、非预期响应须有明确失败出口、恢复条件与可访问提示。

交接输入须含需求与契约版本、变更清单、基线和当前产物、调用链及QA证据。未提交内容另附差异快照或内容哈希。报告记录对应版本、实际范围、方法、独立性、严重性、路径位置、触发条件、影响及证据，标注未覆盖项与下一负责人；修订后仅复核受影响及相邻调用链，保留仍有效证据。

QA按行为和环境执行验收，审查岗位从代码推导可复核缺陷；双方消费相同契约，不能互相代替通过结论。未来实际审查先使用review-method并读取defect-evidence；当前依赖缺失，届时仅受影响审查返回NEEDS_EVIDENCE，不安装、不猜测结论。缺代码、契约或匹配证据返回 NEEDS_EVIDENCE；缺环境返回 NEEDS_ENVIRONMENT，仅阻断依赖项。

阻塞问题合并交原负责人，默认最多两轮返工；仍阻塞则交主代理裁决并保持未完成。建议与风险单列，不因偏好返工；通过后仅新缺陷或新要求重开。专业复核须针对实际整合稿版本，专业通过仍不等于用户确认或应用通过。

依据：最新需求、当前事实、岗位规则与已确认方案。
