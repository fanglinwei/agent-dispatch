## 2. 后续实际审查的输入与前置

开始实际审查前，主代理须提供明确只读派发与下列输入。资料不足只暂停不能归因或无依据的部分，不能靠推测补齐 API 或产品规则。

1. **范围及身份：**基准与目标版本、精确变更路径、未提交修改的归属、对应 R1～R6 范围；采用提交标识或差异摘要标识本次材料。无提交时记录文件差异身份，不为审查创建提交、分支或工作树。后续修复改变身份时，明确哪些原证据失效。
2. **唯一实施契约：**产品字段与校验规则、UI 状态和焦点规格、前端状态转移及适配层契约、容量语义、成功证据、错误分类、输入保留范围。草案建议须经相应确认后才能用于判断实现偏离；未确认处登记未决问题。
3. **真实接口材料：**实际调用入口、请求/响应样例及其来源，特别是 CAPACITY_FULL 的错误包和副作用语义、成功响应必要字段、权限拒绝、超时/5xx、幂等与结果查询保证。不从 HTTP 状态或接口名称推断服务端保证。
4. **验证材料：**实现者直接自测与 delivery_qa 的相关用例、构建身份、环境、命令、退出状态及实际结果；无执行记录标“未执行”。模拟响应只能证明模拟条件下的行为，不能证明服务端并发、容量原子性或幂等性。
5. **技能与安全前置：**按真实 review-method 读取其必需依赖；缺失则停止实际审查。代码检索遵守受审仓库规则。只读查看状态、差异、历史与源码，不运行自动修复，不修改被复核材料；本岗默认不另跑会写缓存或产物的构建/测试，需要新增执行证据时交 QA 或主代理指定安全范围。

当前没有应用差异、源码位置、真实接口样例或执行材料；本轮不具备实际代码审查输入，也没有启动该审查。

## 3. 审查顺序与调用者核查

以下为后续可执行方法，当前均**未执行**。优先从变更向直接调用者和状态消费者追踪，直至足以证明受影响行为；不无条件扩为全仓检查。

| 顺序 | 只读操作 | 必须形成的记录 |

| 1. 固定范围 | 查看仓库状态及限定路径差异；可使用 git status、git diff、git show 等只读命令。核对基准与目标，区分本次差异和他人已有修改。 | 范围、版本或差异身份、相关需求、可用和缺失材料。 |
| 2. 找出影响面 | 从变更的组件、组合式函数、类型或适配函数，定位所有直接调用者、导出、事件入口、响应消费者、相关测试与响应样例。沿报名链定位按钮、表单 submit/Enter、重试和返回导航；沿读取链定位列表选择、详情读取和活动切换。 | 精确路径/行号与调用关系；没有被修改但依赖新契约的调用者也列入。此阶段只记录真实存在的位置，不预设项目路径或新增模块。 |
| 3. 对照契约 | 把每个入口的输入、当前状态、发出请求、结果映射及下一状态与整合稿中的唯一契约逐项对照。类型编译可通过不代表运行时响应已校验。 | 已覆盖分支及遗漏分支；偏差的触发条件、实际与期望行为。 |

| 5. 交付与回归 | 只报告有因果链的代码缺陷，分离未决设计、材料缺失和测试建议；交主代理分配修复。修复后重新核对受影响差异、调用者及有效证据。 | 缺陷清单、复核范围、未覆盖项和剩余阻塞；不以“未发现”替代产品验收。 |

## 4. R1～R6 的状态、容量与恢复检查点

状态名称与完整转移只在整合稿的前端契约位置定义；本表是审查断言，不再建立第二套状态机。断言按最终确认契约执行，当前仍属方法建议。

| 需求/边界 | 代码与调用者必须核查的内容 | 最小缺陷证明或交接证据 |
| --- | --- | --- |
| R1、R2 读取和活动身份 | 加载、正常、空列表、读取失败及详情不存在可区分；不能把异常变为空列表。列表选择、详情、表单、请求与结果使用同一稳定活动标识。切换活动、离开组件或旧请求晚到时，旧响应不能覆盖新上下文。 | 指出响应写入状态的位置、当前上下文核对及缺失条件；用 A/B 活动和相反响应顺序说明可达错误路径，实际运行由 QA 留证。 |
| R3 校验与提交入口 | 规则来自确认字段；非法值不发送请求且保留其他输入；服务端字段错误正确关联，未知字段错误仍可见。所有提交事件走同一规则与门禁；错误摘要、字段标签、键盘提交及焦点遵守唯一 UI 规格。 | 输入约束来源、校验到请求的调用链、错误映射与数据清理路径；没有确认的字段规则先登记未决，不凭偏好报错。 |
| R4 容量预提示 | capacity、confirmedCount 的类型、零值、缺失值及超限值按真实契约处理，不默认无限、不伪造余量。合法快照仅用于预提示；客户端余量不能代替服务端最终决定。 | 实际字段解析和判断位置、受影响展示和可提交入口；异常样例须标明是否真实契约允许。 |
| R4 容量竞争 | 详情原有余量、提交返回 CAPACITY_FULL 时走满额分支，结束忙碌、保留输入、停止同一报名重提且不显示成功。详情刷新失败或较旧可用快照不能撤销较新的满额结果。 | 从适配层业务码到页面状态和按钮门禁的完整链；相关响应顺序和 fixture。服务端最后一名额的原子竞争须另有真实接口证据，仅前端检查不能关闭。 |
| R5 明确结果 | 成功必须符合已确认成功响应契约，不能仅凭任意 2xx、用户输入或无法校验的响应包显示成功。明确拒绝、权限拒绝、满额和未知结果分别映射；成功后后退、重渲染或重试入口不重新发请求。 | 成功判定、错误分类和导航调用者；成功字段需求以实际契约为准，不擅自新增凭证字段。 |
| R6 输入保留 | 网络失败、服务端错误、满额、核对与重试不经过清空逻辑；检查 catch、finally、watch、组件重建与详情刷新。不同活动草稿不串用。保留范围只按确认的会话/导航规则判断，不默认持久保存个人信息。 | 原值从输入到请求快照、错误恢复和渲染的读写链；字段前后对比由 QA 使用去标识化数据记录。 |
| R5、R6 重复事件 | 首次有效提交在首个异步等待前同步设置门禁；按钮、Enter、触控、重试共用处理约束；终态释放正确，所有路径不会永久忙碌。单次页面门禁不被当作服务端去重保证。 | 入口到异步调用的控制流、重复事件到达时可见状态；请求次数及服务端记录数分别证明，不混为一项。 |
| R6 结果未知 | 请求开始后的超时、断网、取消、5xx、响应解析失败不能直接证明服务端无写入。核查未知结果是否保留活动、原请求标识及冻结字段，是否会自动重试或产生新标识盲重提。取消前端等待不等于撤销服务端操作。 | 不确定错误到恢复入口的调用链；“服务端已写入但响应丢失”场景由 QA 取证，缺服务端证据不能宣称安全重试。 |
| R6 安全重试契约 | 只有原操作确定不会再生效，或存在有效的幂等重放保证，才能按契约重发。同一逻辑意图重放保持同标识同内容；同键不同内容、并发同键、有效期及查询“未找到”的语义以真实保证为准。编辑、切换活动或重新挂载不能绕过未决操作。 | 真实服务端契约、适配层实现与所有重试入口的对应关系；仅生成客户端标识、禁用按钮或一次查询未找到不足以证明去重。缺能力交主代理解决，审查岗不新增后台功能。 |
| 相关信任边界 | 仅检查本次链路涉及的响应形状校验、安全文本呈现、权限/错误处理及日志泄漏；不把“无登录”推断为可公开任意报名数据，不在前端新增密钥。 | 具体输入来源、渲染/日志/访问位置及可达影响；证据脱敏，不复制报名个人信息、令牌或完整原始正文。 |

## 5. 缺陷分级、证据格式与交接

以下分级为拟采用的报告约定，供整合确认；优先按可证明影响及触发面判断，不凭猜测提高严重性。

| 等级 | 判断方式与本项目相关示例 |
| --- | --- |
| P0 紧急 | 已证明影响广泛且正在造成严重数据破坏或敏感信息暴露，需要立即阻止相应交付；本稿不推断存在 P0。 |
| P1 高 | 关键报名流程在常见或明确可达条件下错误，例如确认后仍可重复创建报名、把未知结果显示为成功、错误报名到另一活动、泄露报名信息。须有对应调用链和契约证据。 |
| P2 中 | 特定恢复或边界分支损坏，例如 CAPACITY_FULL 未映射、失败清空字段、某一键盘入口绕过门禁；实际等级按影响与触发频度调整，不将示例机械定级。 |
| P3 低 | 不阻断主要流程且有局部影响的可证实问题；纯样式偏好、无影响重构建议不进入缺陷清单。可访问性缺陷按用户实际受阻程度分级，不能一律判低。 |

每条缺陷包含：简短标题与等级；目标差异身份；精确路径和最小相关行号；关联 R 编号与契约来源；前置状态及触发步骤；期望与实际行为；变更点→调用者→错误状态/副作用的证据；影响范围；现有验证能证明和不能证明的部分；建议修复位置及交接对象。建议修复位置不是本岗写入授权。静态推导须说明推导条件，未运行不写复现成功。

缺陷与其他事项分别报告：契约不明记“未决项”，无执行证据记“验证缺口”，技能依赖缺失记“审查阻塞”。未确认服务端幂等能力不能直接报“已存在重复报名缺陷”，但也不能将对应风险记已关闭。主代理接收缺陷并分配 frontend_owner 修复；delivery_qa 接收最小触发与预期，补实际行为证据；UI/产品接收规格疑问；本岗对新差异做受影响范围复核，不修改被审材料。
