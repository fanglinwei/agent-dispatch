# frontend_owner 实施供稿
状态：DRAFT；开发另起任务。本岗负责 Vue 页面、状态与 API 适配，是技术契约提案唯一来源，整合由主代理裁决。

依据：latest-brief.md 确认本期流程；current-evidence.md 确认 Vue 3／TypeScript、适配层、capacity、confirmedCount 和服务端 CAPACITY_FULL，当前界面未呈现该错误。旧稿的 React、无限容量、失败清空及全部 PASS 不沿用。

实施建议：列表、详情、报名表与结果视图分离，名称及路由待定；用判别联合描述载入中、空、就绪、载入失败，以及编辑、校验失败、提交中、成功、明确拒绝、结果不确定。载入错误可重新读取；提交期间锁定入口并防重复触发。服务端确认成功才显示完成；CAPACITY_FULL 显示满额、保留输入并刷新活动信息，禁止伪造成功。

适配层统一解码活动、报名响应和错误，页面消费领域结果。capacity 与 confirmedCount 仅供容量呈现，不能保证提交时仍有名额；类型、缺失值、零值与异常计数语义待确认，数据异常显示不可用并阻止依赖它的操作。API 路径、方法、标识、表单字段及规则、成功凭据、错误包、鉴权、并发裁决、幂等键与结果查询均未查证，暂不固化。

恢复建议：校验失败定位错误并保留全部输入；明确失败也保留输入。断网、超时或响应丢失进入结果不确定，禁止自动重发及直接开放再次报名；须核实未受理且不会迟后生效，或证实幂等覆盖该请求，才开放人工重试；核实成功直接展示结果。机制未证实则阻塞相关重试，交主代理协调证据。

数据边界：仅传送产品确认的必要报名字段；草稿默认只存当前页面内存，不擅自持久化或上传日志。刷新／离开后的保留能力另行确认。展示服务端文案按文本处理，不输出原始响应和个人资料。

顺序与验收：先由产品交付字段与规则、UI 交付状态稿；前端核对实际代码及接口样例，交主代理确认契约后接适配层，再连页面，QA 消费同一契约。开发任务应以受控样例逐项验证正常／空／载入失败、容量满、校验失败、CAPACITY_FULL、连点、断网与响应丢失；断言请求次数、状态、输入保留和成功凭据，并留脱敏请求及截图。构建命令以实际项目脚本核实后执行；构建、浏览器、应用测试现均 NOT_RUN。交接物为契约确认记录、实现差异与复现证据。
