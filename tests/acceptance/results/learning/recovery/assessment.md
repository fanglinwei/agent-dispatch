## 实际执行与输入

主代理在系统临时目录运行 `tests/acceptance/recovery-harness.py`，由它复用 `fixes/fault-harness.py` 与原独立代理产出的 `fixes/save-memory.py`。保存函数指纹保持 `8f2c11dc0bfdbaa780b0531e833ed46e317b16919fb585a68cf36b840bd44a06`。本轮时间、执行脚本/保存函数指纹、进程 ID、退出状态、原始请求和各阶段完整文件指纹见 `replay.json`。

脚本先重新执行原十四组真实进程探针，随后将三个真实中断目录逐字复制为恢复场景。原 `probes/` 保留中断后的完整文件和实际暂存残留，不用手工组装状态代替这次中断。每次恢复和重复提交都启动新的操作系统进程，从已保存输入重新读入；不继承前一进程的内存变量。进程隔离仅验证存储及协调步骤，不冒充新模型上下文的自主判断。

所有条目是原隔离合成 `candidate` 数据，不提升为 `active` 项目知识。恢复者读取原始增量及 SHA-256、完整候选、目标和当前回执；候选对应的修订与受影响条目需一致。模拟请求逐项列出目标和暂存权限。只有暂存的指纹与实际观察记录一致，且内容为该候选的完整字节或本次部分写入的前缀，才允许清理并重新安全保存；这不是凭文件名给未知残留授予清理权限。

## 已有归档的两次提交

`archive-input/` 保存原始增量、已有归档、合并后的归档、当前文件及移除已归档内容后的完整候选。归档已有独立条目和真实测试回执，先将当前条目及相关修订线索合并进归档，再安全更新当前文件。每次归档提交都使用同一个安全保存函数；两次提交由本轮验收协调代码串行执行，不称为跨文件事务。

| 故障点 | 恢复前实际状态 |
| --- | --- |
| 归档替换前退出 73 | 旧归档、完整当前文件和归档暂存仍在 |
| 归档已提交、当前提交尚未开始时退出 73 | 新归档和完整旧当前文件并存，允许临时重复 |
| 当前文件替换前退出 73 | 新归档、完整旧当前文件和当前暂存仍在 |
| 当前文件实际替换后退出 73 | 新归档和完整新当前文件均在，成功回复尚未产生 |
| 当前文件原子替换抛出异常 | 新归档和完整旧当前文件仍在，返回 migrationCompleted=false |

五组恢复前均实际核对条目及回执至少保有一个完整副本。新的进程完成迁移，原归档条目及回执逐字保留，新归档 revision 2；当前文件 revision 2，已迁移条目和回执从当前文件移除。每组再以新进程重试，返回 unchanged，两份目标完整字节不变，不增加经验、回执或修订，且无暂存残留。保留中间、恢复后和重试后的完整快照，不能只凭迁移完成标志判断成功。

## Unicode 说明与覆盖边界

保存代码实际执行 NFC 规范化、casefold 与文件身份检查。主代理修正了原集成说明遗漏 NFC 的表述，并实际以 `café.md` 与 `cafe\u0301.md` 的两个等价授权路径调用保存函数：返回 authorized_path_alias，目标、暂存及其他文件均未创建。该输入只支持 NFC 等价路径这个结论，不证明全部 Unicode 或各文件系统别名规则。

本轮覆盖三组可写恢复、三组只读接手、五组两步归档恢复及一次 NFC 别名拒绝。它们是固定输入、单写者、明确故障点下的进程级验收；不是模型自主恢复评测、生产环境、断电、硬件损坏、多主并发或跨文件事务验证。真实项目仍由获授权主代理核对来源、候选、职责、单写者前提与恢复证据。离线 `npm test` 只验证保存的真实产物与脚本指纹，不再次执行 Python 或模型。
