# 路径与安全保存修复：主代理集成核对

本轮只修复配置路径冲突与覆盖中断保护，未安装插件、迁移真实用户项目或执行 Git 写操作。原始纠错/保存/新上下文复用、文档供稿及专业复核保持其原时间、身份和来源，不冒充本次重跑。

## 修复前证据

`red-reproduction.json` 记录按旧规则允许的默认路径和原地覆盖方式执行的两个操作实验：`protocol` 的记忆与协议同路径，写记忆后协议不再保留；对唯一目标写入部分字节并退出 71 后，旧记录和同文件历史都无法解析。这证明规则没有排除这些失败方式，不声称存在已安装的旧运行引擎。

独立基线 `/root/fix_baseline` 的原始 `baseline.md` 保留：它自行选出了安全岗位路径，不能称为角色必然发生命名错误。其保存方案要求已有归档父目录，当前样本不满足，未执行；方案用经验证归档保护旧目标，仍采用原地覆盖且不通用于已有不同归档。本轮没有把该静态方案冒充真实失败/成功保存，也没有作统计效果比较。

## 当前实际配置

`/root/fix_paths_behavior` 在全新上下文读取当前 Skill 输出 `paths.md`、`paths.json`。新角色避开 `protocol` 和已占用 `protocol-role`，选 `protocol-role-2`；旧角色保留稳定 `protocol` 与 `records/protocol.md`，指引使用真实路径。针对路径别名、缺暂存授权和只读任务仅批准目标的场景，分别停止相关配置/保持待保存，没有扩权。

主代理在临时目录按方案实际生成 `configuration/` 两个项目，解析 TOML，逐字核对原专业正文、模型、附加指引及旧记忆。协议与目标路径不同，所有目标/暂存路径明确，未提前创建暂存或空归档。旧记忆完整字节保留，指纹见 `verification.json`。

另将原团队三个阶段的隔离副本升级为当前协议并补充精确暂存授权，模拟批准范围见 `team-migration.json`；原角色 TOML、模型、定制和记忆原字节不变。增岗后仍保留增岗前入口前缀。本轮实际解析六份 TOML，格式及必需字段通过；新上下文复用检查与全树快照见根 results/repeat-review.md、repeat.json。早期版本的重复检查原报告另保留为本目录 repeat-before-layout.md，最终配置使用最后一次新上下文检查结果。

## 当前实际保存

`/root/fix_save_behavior` 独立读取当前协议后产出 `save-memory.py` 和原始 `save-report.md`；该代码是验收产物，不复制或安装为项目运行引擎。主代理读取实际源码并核对其指纹未在运行后改变，实际执行它形成以下十四组结果。它仍依赖调用方保证唯一写者和已合格候选；结构验证不代替来源、确认和职责核对。

| 实际执行 | 观察结果 |
| --- | --- |
| 正常保存、首次创建、首次归档 | 进程退出 0；目标逐字节等于候选，回执/修订一致，无残留暂存。归档必要父目录实际按需创建。 |
| 暂存部分写入后退出 | 在真实输出流中只写候选前三分之一、flush/fsync 后 `os._exit(73)`；目标仍为完整旧版。 |
| 原子替换前退出 | 到达替换调用前 `os._exit(73)`；旧目标完整，候选尚未成为有效目标。 |
| 原子替换后退出 | 实际替换后、函数回复前 `os._exit(73)`；目标完整等于新候选，回执/修订可核对。 |
| 仅目标授权、已有暂存、暂存符号链接、目标硬链接别名 | 返回 pending，未覆盖目标或原暂存；链接指向的受保护文件不变。 |
| 暂存后目标同修订字节变化 | 实际注入新字节；提交前指纹复查识别变化，保留更新后的目标，没有用旧候选覆盖。 |
| 替换失败、不支持替换 | 返回 pending，旧目标保持完整，不降级为原地覆盖。 |
| 提交后目录同步失败 | 核对实际目标完整后报告 saved，同时保留同步失败信息，不盲目回滚新版本。 |

原始输入、真实退出码和目标/残留字节保存在 `saving-input/`、`probes.json`、`probes/`；主代理对照原始输入检查完整字节与首个 JSON 记录，核对实际增量原始 SHA-256 和回执。输入条目明确是合成 candidate 存储数据，不是凭空产生的 active 项目知识。链接情景的导出文件是普通字节快照，原始链接构造和故障注入均保留在可重放的 `fault-harness.py`。

执行者另在自己独占临时目录运行二十项标准库直接检查，原报告和测试源码分别存为 `save-report.md`、`independent-check-source.txt`；后者保留原临时目录布局，是源码存档，不作为仓库内可直接运行的脚本。原报告对“Unicode 规范化别名”的描述偏宽：实际代码采用 casefold 与文件身份检查，不据此声称通用 Unicode 规范化处理。完成声明以主代理十四组实际进程探针、具体路径输入和离线断言为范围。

## 覆盖与限制

当前源码明确要求所有实际输出路径无冲突、旧稳定标识保留、指引使用实际映射；只读和旧授权不能推导出新暂存权限。旧协议缺少安全保存时，在下次显式配置提出受影响迁移，普通任务不自动升级。记忆和归档都执行同目录独占暂存、完整验证、目标复查、原子替换、整体回读，不把同文件 history 当作独立备份。

十四组进程探针是单次、隔离、带明确注入点的真实调用，不是断电/硬件损坏、恶意竞态、多主并发或跨文件事务测试；原有预置恢复情景仍保留为决策证据。归档与当前文件的先后提交依然由主代理协调，本轮未声称完整归档迁移故障测试。宿主原生角色加载、真实插件升级和长期学习效果未验证。最终离线套件以本轮终端 `npm test` 结果为准；源码哈希清单仅验证证据对应，不替代行为执行。
