# 学习实现验收

实际单次基线 /root/learning_red 读取旧 Skill 后只规划角色、许可与 AGENTS 三个路径，没有角色学习映射、记忆或持久化流程；/root/learning_green_config 读取新版后给出协议、空记忆、角色指引、持续维护和只读边界的完整方案。命名由主代理在模拟批准前统一为 content-creator，原始两份方案保留。基线与候选不是统计比较，也不是证明模型本身不会反思。

主代理按新版 Skill 在临时项目实际生成初始与新增岗位，固定原正文加模板指引、完整许可、稳定映射和空记忆。TOML 原生解析通过。原岗加入的模型及用户审稿定制在新增时字节不变。新上下文 /root/learning_repeat 读取实际配置后独立判断复用，主代理全树哈希前后相等。

/root/learning_repair 实际读取完整岗位、入口、协议和 revision 0 空记忆，核对活动与项目约定，将草稿周日纠正为周一；消息在交付前报告已核实依据。角色仅写独占稿件/报告/增量；主代理独立核对实际产物和来源哈希，基于完整 revision 0 写入条目、revision 1、回执并整体回读。原始增量 SHA-256 与回执相等，未修改角色原始增量。

/root/learning_reuse 以 fork_turns:none 接受另一活动任务，派发不含待测答案；实际读取 revision 1 与 active 条目、核对当前约定哈希，正确生成周二提示。报告明确复用的条目标识与依据，没有沿用旧活动的编号 0。报告无增量，记忆正文、回执、修订号保持原字节；这是正常完成无需保存的实际任务，不以制造经验为成功。

只读角色实际检查独立项目并交接待保存增量，主代理全树 8 文件前后哈希相等。13 组边界输入及子情景的完整原始报告和主代理逐项判断见 boundary-assessment.md。旧项目迁移与角色改名另在隔离副本中实际执行并解析：定制、模型与原正文保留；改名后稳定 key 与完整记忆字节不变。其余生命周期动作只验证决策，没有声称真实执行。

完成声明范围：项目配置与学习指令、实际纠错—主代理保存—新上下文复用、幂等与只读边界。未验证原生角色加载、长期稳定性、真实崩溃或多主并发；不声称由此证明运行时强制隔离或模型权重更新。
