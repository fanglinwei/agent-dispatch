# Agent Dispatch Doc

仅在用户显式调用本 Skill 或明确要求使用它时运行；插件安装时接受宿主实际注册的限定名称。适用于各类项目的实施文档，不执行实际开发、内容制作或发布。已有团队可以直接使用，不要求另一个 Skill 同时安装；团队配置是前置条件，本 Skill 不选岗、增岗或改写角色与 Skill 绑定。

## 1. 核对团队与实施目标

读取适用项目规则、实际岗位定义、已确认目标与交付标准、相关实际产出、项目 Skill 使用关系和文档入口；代码检索遵守项目规则。已有团队合适时直接复用，核对其责任覆盖和允许的调用方式，不制造角色配置改动。

团队不存在，或目标需要当前岗位无法承担的职责时，列出具体缺口和受影响文档，交接给 `agent-dispatch` 的配置流程；不要自行新建岗位。独立安装本 Skill 时也遵守同一前置条件，可先准备不受阻内容，团队产出部分标为 `PARTIAL`。用户明确同时使用两个 Skill 时，先完成团队配置，再回到本入口。

从材料核实事实，仅询问影响本次文档的未知决定。优先使用可用的 `grill-me` 及其实际访谈方法；缺失或不可调用时，按决定依赖分轮提问，编号并给推荐答案，等待回答后继续，不假装调用或要求安装。不重新询问仍有效的整体目标、技术栈或已确认岗位。

## 2. 确认文档方案

读取 [团队实施文档方法](references/project-documents.md)。以最新目标、实际事实及团队专业设计编写自洽的新实施依据；旧文档仅供必要背景核实。已有按本流程确认的当前文档则维护受影响部分，不重复生成。

展示文档范围、精确路径、每份唯一写入者、全部岗位的具体贡献与复核、依赖顺序、预期深度、需更新的文档入口、未知项及限制。文档入口可以包括 `AGENTS.md` 中的实施依据指向，此权限不扩张为修改岗位定义、职责分配或 Skill 绑定。

用户确认方案后执行；已确认且范围未变时继续，不重复索要。此次方案确认不代表提前接受尚未形成的文档内容。

## 3. 按岗位实际编写与复核

按参考组织各岗位实际贡献领域设计、实施安排或专业检查方法。主代理保留跨岗裁决、集成、关键证据复核和最终交付判断；共享文档由唯一写入者整合，其他岗位供稿或复核，独立输入才并行。

每次派发明确目标、权威资料、允许动作、精确读写路径、已配置的适用 Skill、验收及返回证据，遵守模型、委派与权限规则。开始相应工作前读取真实技能及必需依赖；必用能力缺失只暂停受影响任务，不擅自安装或替换。审查岗位编写检查方法不等于执行实际代码审查。

若不能实际调用所需岗位，说明未参与岗位和未覆盖内容，将团队共同产出部分标为 `PARTIAL`，不能把主代理独写描述为团队交付。新内容先标为 `DRAFT`，区分事实、已确认要求、设计建议与未知项，执行结论须有证据。

## 4. 内容确认与实施交接

核对所有岗位都能定位具体工作、输入输出、交接、依赖和完成条件；关键规则、契约、状态与验收足以据此执行，跨文档一致，引用有效，不依赖旧文档才能理解。未执行检查保持未执行，不用文档完成代替项目完成。

向用户展示草案、各岗实际贡献、复核结果与未决项。专业复核和用户内容确认后，才将新文档标为已确认实施依据，更新约定入口，旧材料保留为历史。后续实施由新的项目任务推进。

后续更新按已确认变化维护；涉及新增岗位或重分职责的部分交回配置流程。返回文件、维护负责人、实际参与、校验与确认状态，明确 `PARTIAL` 和未覆盖范围。
