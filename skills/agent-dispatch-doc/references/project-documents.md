# 由配置后的团队编写新的实施文档

在显式调用 `agent-dispatch-doc` 时使用。文档是后续各岗位开展项目工作的共同实施依据，必须先核对团队配置；已有岗位适合时复用，确有缺口则交回 `agent-dispatch` 的配置流程。本 Skill 不增岗，不以文档任务跳过团队前置条件，也不要求另一个 Skill 同时安装才能使用已有团队。

## 新文档的依据与状态

以最新用户目标、约束、实际项目事实和团队专业设计为依据，形成可独立阅读的新文档或文件集。旧文档仅供必要背景查证；需要采用的结论重新核对后写全，避免用“同旧文档”代替规则、接口或工作说明。不自动继承旧文档的权威、进度和验收结论，也不自动删除或覆盖旧文件。

方案中确定新文档的精确路径和单一入口。首次形成的内容标为 `DRAFT`，区分已核实事实、已确认要求、团队设计建议及待决定项；重要未知影响实施时交用户澄清。每项已有成果或执行结论有实际证据，计划、文档完成与功能完成分别记录。

用户确认文件方案后才编写；内容完成并经专业复核后，再请用户确认新文档成为实施依据。文件方案获批不等于接受尚未形成的设计。草案可被引用，但不能被标成已确认基线。

## 先配置，再按岗位实际产出

1. 主代理核对已配置岗位、协作及 Skill 规则与其现有证据。既有团队适合时记录核对结果，不制造配置改动；发现缺口交回团队配置。尚不能原生调用的岗位，在环境允许时由主代理通过通用委派携带已读取的实际职责；注明这不证明原生加载成功。
2. 把每个岗位映射到本项目的具体工作及对应文档。每个岗位至少实际贡献自己的领域设计、实施安排或专业复核方法。仅承担后续实现、审查或测试的岗位，也应具体定义自己的方案、检查点、输入输出及完成条件，不能只列岗位简介。
3. 每份共享文档指定唯一写入者，其他岗位供稿或复核；按依赖安排贡献，独立输入才并行，不要求所有岗位两两互审。派发具体目标、资料、Skill、允许动作、精确读写路径、交接和验收，默认维护负责人不等于整目录写权限。
4. 文档负责人整合已提供的专业内容，主代理处理范围与跨岗契约冲突。各专业岗位复核受其负责范围影响的整合结果；用供稿或复核结果记录实际参与，主代理不替专业岗位虚构结论。

岗位调用、模型选择和写入权限遵守环境规则；代理配置由允许的主责写入者完成，不能以编写文档授权绕过配置限制。若不能实际调用所需岗位，可以完成不受阻的草案或准备，但团队共同产出要求标为 `PARTIAL`，说明未参与岗位与未覆盖内容，不把主代理独写声称为全团队交付。

## 工作内容与颗粒度

参考三国霸业文档中产品、规则、技术、UI/美术、进度和测试的细化程度，采用“可执行、可交接、可核验”的标准；不复制其游戏内容，也不强制所有项目分成六份文档。按项目领域组织，一份文档可以覆盖多个领域，但所有岗位的实际工作要有清晰定位。

每个岗位的工作记录至少包括：本项目责任与边界、具体工作或设计、输入与前置条件、输出与交接对象、依赖及顺序、验收方法与证据要求、已确认决定及未决项。仅写“负责 UI”“保证质量”等职责口号不足以指导实施。

以下是软件项目中可检查的深度；其他项目按自己的内容规范、生产环节、交付载体和检查方法表达同等细节，跳过不适用项。

| 领域 | 至少细化到可执行的内容 |
| --- | --- |
| 目标与端到端流程 | 受众、范围与排除项、优先级、完整使用或交付流程、分支与恢复、完成标准及需求到验收的对应。 |
| 领域规则与内容 | 操作或生产步骤、输入与效果、数值或格式要求、顺序、合法性、取消/拒绝/边界；适用时给出可核对示例。 |
| 技术与生产方案 | 模块或环节的主责、接口和数据/内容契约、状态变化、集成、兼容、存储、构建或生产方式、失败处理与交接。 |
| 交互与视觉/表达 | 信息层级、页面或载体、组件、完整状态、布局及平台约束、可访问性、素材规格、资源交接和符合性检查。 |
| 实施与协作 | 任务主责、依赖、阶段入口与出口、交接物、阻塞、维护责任和后续更新方式；执行状态只按证据记载。 |
| 审查与验收 | 审查范围与方法；测试或检查的前置条件、输入/操作、预期、边界及失败复现、通过标准、证据和未覆盖范围。 |

同一规则、接口或状态由一个位置定义，其他文档引用新文件中的该定义；确认输入输出与各岗交接一致。复用项目已有的需求、任务和用例编号，不另建平行台账。尚未执行的检查标为未执行，不为了“文档完整”填写通过结论。

## 复核、确认与维护

交付草案前核对：

- 最新目标和完整流程有覆盖，项目团队所有岗位都能定位自己的具体工作、交接和完成条件，有实际供稿或复核结果。
- 专业规则、实现契约、交互和验收之间无未处理矛盾；工作有足够细节，关键部分不依赖旧文档才能理解。
- 每份文档有维护主责与唯一写入安排，Skill 使用关系可从项目协作入口定位；事实、目标、建议、进度与执行证据未混写。
- 内容、相对链接和入口引用可用，保留旧文档；专业未决项和未完成参与如实列出，影响实施的问题不能被描述为已解决。

向用户展示草案位置、各岗实际贡献、复核结论和未决项，取得内容确认。确认后才把新文档标为已确认实施依据，并更新已约定的项目入口和 `AGENTS.md` 指向；旧材料保留并明确历史身份，避免两个入口都声称是当前依据。

后续任务按新文档实施。团队配置流程完成增岗或职责变化后，本 Skill 根据已确认交接同步修订受影响工作、交接、Skill 引用及文档主责，不反向修改角色定义或技能绑定。保留仍有效内容，实质目标或设计变更只确认受影响部分，不因再次调用而重新生成同一套文档。
