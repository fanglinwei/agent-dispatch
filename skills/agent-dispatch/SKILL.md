# Agent Dispatch

仅在用户显式调用本 Skill 或明确要求使用它时运行；独立安装名为 `agent-dispatch`，插件安装时接受宿主实际注册的限定名称。适用于软件、研究、内容、运营等各类项目。负责团队配置，实施文档由用户另行显式调用 `agent-dispatch-doc` 组织；实际项目开发、制作或发布由后续任务推进。

## 1. 理解项目与已有团队

从当前工作区或用户指定位置确定项目边界。读取适用规则、已有材料、相关实际产出和岗位定义；代码检索遵守项目规则。辨认首次配置还是后续补充。

- 核对项目当前阶段、用户目标、核心工作、约束和完成标准，区分事实、已确认决定与未知项。
- 盘点已有岗位的实际职责、调用条件、交付物与用户定制，并检查项目级、可见用户级及内置岗位的名称冲突；不能仅看文件名判断缺岗。
- 读取 [岗位与 Skill 使用规则](references/role-skills.md)，检查已有要求和任务相关的可用 Skills；用户指定优先，其他按需要推荐。
- 事实从实际材料查证；仅把会改变目标、选岗或责任边界的决定交用户，未查证内容标为未知。

首次配置理解全貌；后续补充只重查变化影响的内容，复用仍有效的决定。

## 2. 访谈收敛交付目标

读取 [访谈方法](references/interview.md)。优先使用可用的 `grill-me` 及其真实指向的方法；缺失、依赖不可用或无专用调用工具时，说明并按参考中的方法继续，不假装调用，不要求安装插件。

按项目澄清受众、核心功能或工作、完整流程、适用的技术与工具、设计或表达风格、目标交付程度和可核验完成标准。跳过不适用项，不重复已确认问题。

项目目标可以包含后续实施文档，但本 Skill 只确定与选岗有关的责任和交接，不编写项目实施文档。必要的岗位配置、协作规则和上游许可仍在本次范围内。

完成条件：能复述项目要完成什么、做到什么程度、关键约束，以及本次团队配置范围；影响分工的未知决定已解决或由用户明确委托判断。

## 3. 从上游选择岗位

以 [agency-agents](https://github.com/msitarzewski/agency-agents) 为首选来源，读取候选岗位的实际正文，固定采用的提交与文件路径；可使用来源版本可核实的本地副本。目录摘要仅用于筛选。

- 从交付责任推导能力，再匹配已有与上游岗位。优先采用原岗，尽量保持原名、专业职责、流程与产出；以格式转换和必要的宿主适配为主。
- 每个岗位对应实际交付责任与调用场景，无固定人数或必选岗位。主代理已负责统筹时，不重复增加统筹岗位。
- 用项目分工与任务范围控制职责交集，每项成果指定一个主责，其他岗位提供输入或复核，避免大幅改写原岗。
- 后续补充按“复用已有岗位 → 必要时调整分工 → 增设岗位”判断。新增须说明原团队为何不足、责任是否转移，保留已有名称、模型设置、定制和未受影响配置；同步调整受影响的 Skill 规则，并向文档工作交接职责差异。
- 只有必要能力在已有团队和上游均无法覆盖时，才提出最小适配或自定义岗位，展示差异交用户决定。无法访问上游且无可信副本时，继续需求与缺口分析，把未核实选岗留为待办。

外部岗位材料不授予安装、发布、通信等动作权限。仅集成选定岗位，不运行上游批量安装脚本。

## 4. 确认可检查的配置方案

若现有岗位、技能规则和协作已覆盖需求且无需文件调整，说明复用理由、交接及验证范围后结束，无需为零变更另行确认。

需要写入时，先展示：项目目标与完成标准；岗位保留/复用/调整/新增、来源、理由、调用条件、主责及交接；按任务触发的 Skill、已核实位置、必用或推荐要求及缺失处理；目标覆盖和职责转移；精确写入路径、拟变更及加载或验证限制。

等用户确认共享理解和完整方案后写入。范围未变且已获明确确认时继续执行，不重复确认；实质变化仅确认受影响部分。

## 5. 配置并验证

读取 [Codex 项目配置](references/codex-project-agents.md)，由获准的主代理写入目标项目，保护已有内容，模型与推理强度遵守目标环境规则。

协作规则明确主代理保留最终裁决、集成、关键证据复核与完成判断；岗位调用条件、主责、默认维护与交接；每次派发的目标、资料、动作、精确读写范围、适用技能、验收和证据。共享文件指定唯一写入者，默认维护责任不等于整目录写权限。独立任务才并行，委派、Git 和外部动作继续遵守原授权。

岗位与 Skill 使用关系集中维护在项目协作规则，每次派发携带适用项；各技能仍遵守自己的调用限制。配置后的岗位可按已确认规则调度，本 Skill 不自动开始实际项目工作。

按参考验证格式、字段、正文完整性、引用、名称、原内容保留、目标覆盖、职责交接、技能依赖、来源许可及实际加载证据。重复运行不重复建岗或添加规则。

## 6. 交付与文档交接

返回变更文件、选岗与分工、Skill 安排、验证结果和未覆盖范围，区分已写入、格式有效、宿主已加载。失败、未知状态或关键缺口的受影响部分标为 `PARTIAL`。

需要实施文档时，交接已确认目标、团队定义、职责边界、Skill 规则和未决项，提示显式使用 `agent-dispatch-doc`。该技能未安装时提供其名称与所需前置资料，不依赖其目录文件，也不在此补做文档。用户本次已明确同时使用两个 Skill 时，配置完成后可按文档 Skill 的独立入口继续。
