# 配置项目岗位学习

首次配置、增岗、岗位迁移及旧项目补齐学习时读取。运行协议以[项目学习协议模板](../assets/learning-protocol.md)为唯一正文；生成前实际读取，将其放入目标项目，使普通任务和独立安装的文档 Skill 都能从项目入口使用，不依赖本 Skill 的安装目录。

## 配置与路径

在完整方案中展示精确新增/修改路径、映射、岗位读取范围和主代理日常合并授权，随团队方案一起确认。旧方案只批准角色 TOML 时，学习文件属于新增受影响范围，不能假定已获确认；已确认当前完整范围则不重复询问。

| 默认项目相对路径 | 内容及写入者 |
| --- | --- |
| `AGENTS.md` 已有协作区块 | 主代理维护学习入口、稳定映射、授权与派发约定。正式职责保留在原处。 |
| `.codex/agents/<原配置文件>.toml` | 主代理保留完整专业正文，仅追加简短项目指引；记录实际适配。 |
| `.codex/agent-memory/protocol.md` | 主代理复制学习协议模板，成为项目日常运行约定。 |
| `.codex/agent-memory/<role-key>.md` | 主代理用[空记忆模板](../assets/role-memory.md)初始化；已有记录保留。 |
| `.codex/agent-memory/archive/<role-key>.md` | 有归档需要且获准时才由主代理创建；不提前建空目录或文件。 |
| `<实际记忆或归档路径>.pending` | 主代理在获准保存时独占创建的同目录暂存文件，验证完整后原子替换对应目标；配置时列出精确路径，不提前创建。 |

已有等效权威协作/记忆结构时沿用其精确路径，核实后适配协议，不新增重复台账或覆盖既有定制协议。协议与岗位记忆分开，角色读取入口时能确定两者；首次 `role-key` 可用安全配置文件主体（小写字母、数字、连字符），持久记录后不再从显示名重算。保留已确认的旧标识；同岗多个执行实例共用同一记忆。检查大小写、路径解析和符号链接，访问不越出获准项目根。

生成方案前，列出协议、角色配置、各岗当前记忆、归档及其 `.pending` 的实际路径，检查规范化后的唯一性和文件/目录前缀冲突；已有文件还核对符号链接与硬链接别名，不跟随暂存文件的符号链接。同岗多实例共用一份映射不算重复目标。默认布局将 `protocol` 列为新 `role-key` 的保留名，遇到此名可用 `protocol-role`，仍冲突则选唯一安全标识；自定义布局仍须检查全部实际路径，不能只靠保留名。已有稳定 `role-key=protocol` 不改标识，沿用不冲突的既有记忆路径或在已确认迁移中选另一精确路径。指引据实际映射渲染，不能仅替换标识后留下默认路径。冲突未解决前不写任何相关配置。

## 生成项目协作入口

在原协作区块加入下面五项实际内容，不把占位符写入最终项目：

1. 学习协议的项目相对路径，以及“每次岗位任务开始前实际读取协议与本岗相关记忆，检查来源适用性；失败/纠正时立即核实和修正，结束时简短复盘，增量按协议交接”。
2. 集中映射表：稳定 `role-key`、实际调用名、角色配置、当前记忆、按需归档路径；主代理是唯一记忆维护者。此表不重复正式职责。
3. 精确授权：岗位只读上述项目入口/协议/本岗记忆及本次获准材料，只写任务独占产物；主代理获准在列出的记忆、归档及各自精确 `.pending` 路径合并日常学习，并在项目根内按需创建这些路径必需的父目录，暂存权限仅用于该目标的安全保存。旧授权只含目标文件时不推导出暂存写权限，补齐授权前交接待保存。协议或角色配置调整另按配置授权处理。当前任务/Skill 只读约束及明确保存例外按协议处理。
4. 每次派发携带：项目根、`role-key`、协议与记忆路径、读入修订号（未知时要求读取后报告，不编造）、本次精确读写范围、`task_id`、实际 `dispatch_id`、任务目标和原验收/返工状态。直接原生调用时由角色指引查找映射，报告宿主真实标识或主代理分配的任务内标识。
5. 主代理按协议串行核对增量、权限、来源和当前修订，经同目录暂存、验证、原子替换后整体回读，不原地截断有效记录；单写者是运行前提，不是跨进程锁。没有增量不写，不把候选/未保存当作原任务失败；不自动开始项目制作或增加 Q3 之外的触发点。

## 角色指引与已有角色

在 `developer_instructions` 的完整上游/用户正文之后，追加[角色读取指引模板](../assets/role-learning.txt)，将 `ROLE_KEY` 替换为稳定标识；已有等效结构时改用其实际协议、入口和记忆路径。作为必要项目适配，源注释如实记录“保留原正文，追加项目学习入口”。

只使用已支持的 `developer_instructions`，不新增 `memory`、`learning` 等原生 TOML 字段。路径使用目标项目实际相对路径；不复制开发机或插件的绝对位置。原正文逐字保留，实际追加正文可从来源记录中定位并核对；不得把“仅格式转换”留为不实适配说明。

既有角色更新前读取完整内容与用户定制，复用已有映射/指引；没有映射时下次显式配置迁移，保留名称、模型、原专业正文、许可及其他定制。改名、替换、拆并、停用按协议迁移，先展示受影响路径。重复运行不清空记忆、不重复追加入口。

旧协议已有学习记录但缺少安全保存或暂存授权时，显式配置仍须提出受影响的协议/授权补齐，不能仅凭文件存在判为零变更。已有等效安全保存结构核实后沿用；不覆盖其定制，不修改有效记忆正文。普通任务不借此升级协议或扩大写入权限。

## 验证与交付

解析 TOML，逐字核对原正文及预期附加指引；实际读取生成的项目入口、协议、每岗记录，核对稳定标识、格式版本、初始修订、路径唯一性、实际指引、目标及暂存授权和既有内容保留。没有证据不预填 `active` 经验，不预建 `.pending`。重复检查同一项目应为零变更；有真实失效条目才处理受影响部分。

返回配置写入、格式有效、宿主加载、学习行为四种证据。本次配置不试运行项目任务；学习闭环另在获准任务或隔离验收中检验，文件存在不证明已纠错、持久化或新上下文复用。
